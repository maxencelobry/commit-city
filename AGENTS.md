## Collaboration preferences

- Execute clear product requests directly; do not repeatedly ask for confirmation.
- Work through the task before reporting completion. Keep progress updates minimal unless blocked.
- Treat visual and functional changes as one deliverable: verify the running site, not only source code.
- Run relevant tests or checks before claiming a change works.
- Create a normal Git commit for each meaningful completed change. Never amend, rebase, squash, or force-push published history.
- Keep the project lightweight: prefer the existing Express and vanilla front-end structure over adding large frameworks.
